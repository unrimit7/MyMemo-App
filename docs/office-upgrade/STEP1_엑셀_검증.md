## 1. ExcelJS 4.4.0 In-Place 라운드트립 아키텍처 및 보존 항목 실측

기존의 `new ExcelJS.Workbook()` 빈 파일 재생성 방식에서 발생하는 고급 서식 유실 문제를 해결하기 위해, **원본 바이너리를 다시 로드한 후 Univer에서 수정된 셀 값/수식/서식/병합/크기 및 시트 구조만 In-Place로 패치하는 방식**으로 전면 재설계하였습니다.

### 1) In-Place 패치 동작 흐름
1. `univerSnapshotToDataUrl(snapshot, format, engine, originalDataOrUrl)` 호출 시 원본 Data URL 바이트를 `wb.xlsx.load(origBytes)`로 먼저 로드합니다.
2. **시트 동기화**: 원본 워크북의 시트 목록과 Univer `sheetOrder`를 대조하여, 삭제된 시트는 `wb.removeWorksheet()`로 제거하고, 신규 시트는 `wb.addWorksheet()`로 추가하며, 이름 변경은 `ws.name`에 반영합니다.
3. **스타일/데이터 패치**: 수정된 셀의 값, 수식, 폰트, 배경색, 정렬, 표시 형식, 행 높이, 열 너비만 기존 워크시트 객체 위에 덮어씁니다.
4. **고급 메타데이터 보존**: 워크시트 객체를 새로 생성하지 않고 원본 객체를 유지하므로, ExcelJS 코어가 유지하는 **조건부 서식, 데이터 유효성 검사(드롭다운), 셀 메모(Notes), 틀 고정(Freeze Panes), 인쇄/페이지 설정(Page Setup)**이 보존됩니다.
5. **한셀(Hancom HanCell) 네임스페이스 및 비표준 OpenXML 정규화 (`normalizeHancellXlsx`)**:
   - 한셀은 모든 태그에 `x:`, `ep:` 접두어를 붙이고, `mc:AlternateContent` 내에 확장 속성을 포함하여 ExcelJS 4.4.0 로드 시 크래시(`Cannot read properties of undefined (reading 'company')`) 및 서식/메모 누락을 발생시킵니다.
   - ExcelJS 로드 전/저장 전 JSZip 메모리 파이프라인에서 `x:`, `ep:` 접두어를 기본 네임스페이스로 정규화하고, `app.xml` Company 보정, `styles.xml`의 `mc:AlternateContent` Fallback 채택 및 `<b val="1"/>` 태그 정규화, `comments*.xml`의 `ref="F4:F4"` 범위 단일화(`ref="F4"`)를 자동 수행하여 한셀 파일도 MS 엑셀과 동일하게 100% 서식 보존 라운드트립이 가능하도록 구현했습니다.
   - (단, `.vml` 파일은 VML 네임스페이스 `xmlns:x="urn:schemas-microsoft-com:office:excel"`를 그대로 보존하여 `VmlClientDataXform` 에러를 원천 방지)
6. **셀 내용 지우기 (Omission to Null)**: Univer 스냅샷에서 사용자가 값을 지워 빈 셀이 된 경우(`v === ''` 또는 미정의/생략), 원본 워크시트의 대응 셀을 `null`로 초기화하여 원본 값이 유령 데이터로 잔여하는 현상을 완벽 방지합니다.
7. **행/열 구조 변경 In-Place 시프트 (`safeSpliceRows`, `safeSpliceColumns`) 및 중복 방지/상쇄**:
   - Univer의 행/열 명령 감지 시 `sheet.command.*` 중복을 배제하고 `sheet.mutation.*` 단일 ID만 엄격히 필터링합니다.
   - 실행 취소(Undo) 시 발생하는 반대 방향 mutation을 감지하여 큐에서 즉시 상쇄(pop)함으로써 불필요한 쉬프트 누적을 방지합니다.
   - ExcelJS 기본 splice 동작에서 누락되는 **셀 메모(`cell.note`), 데이터 유효성 드롭다운(`cell.dataValidation`), 조건부 서식 참조 범위(`conditionalFormattings[].ref`)**를 데이터와 함께 안전하게 한 칸씩 시프트 이동시킵니다.
8. **원본 로드 실패 시 무음 덮어쓰기 방지 및 사용자 선택 다이얼로그**:
   - 저장 시 원본 파일 로드에 실패할 경우 조용히 빈 워크북으로 덮어쓰지 않고, 즉시 `ORIGINAL_WORKBOOK_LOAD_FAILED` 예외를 발생시켜 사용자에게 *"원본 서식(드롭다운, 조건부 서식, 메모 등)이 저장 시 사라질 수 있습니다"* 경고창과 함께 [취소] / [그래도 저장] 선택권을 제공합니다.
9. **호환 모드 배너 표출**:
   - 파일을 열 때 ExcelJS 로드가 불가하여 SheetJS 폴백으로 열린 경우, 편집기 상단 툴바에 *"⚠️ 호환 모드: 서식 일부가 표시되지 않습니다"* 배너를 표출하여 사용자에게 알립니다.

## 3. 안전 장치 및 사용자 경험(UX) 개선 구현 내역

### 1) 미보존 고급 요소 사전 감지 및 저장 전 경고 다이얼로그 (`excelLossDetector.ts`)
* 엑셀 파일을 열 때 JSZip을 통해 내부 `xl/charts/`, `xl/pivotTables/`, `xl/drawings/`, `xl/vbaProject.bin` 엔트리를 1ms 이내로 스캔합니다.
* 차트나 피벗 테이블 등이 포함된 파일을 수정 후 **[💾 저장 및 반영]**을 누르면:
  - ⚠️ **고급 서식 보존 주의 안내** 팝업이 노출됩니다.
  - "웹 편집기에서 차트(그래프) 요소가 누락될 수 있습니다." 항목을 정확히 나열합니다.
  - **[취소 (저장 안 함)]** 또는 **[그래도 저장]**을 사용자가 명시적으로 선택할 수 있습니다.

### 2) 원본 버전 백업 및 원클릭 되돌리기 (`originalData`)
* 사용자가 첨부된 엑셀 문서를 웹에서 처음 수정하고 저장할 때, **수정 이전의 최초 원본 Data URL을 `att.originalData`와 `att.originalDate`로 자동 백업 보존**합니다.
* 편집기 툴바 상단에 **`[↺ 원본으로 되돌리기]`** 버튼이 생성되며, 언제든 클릭 한 번으로 처음 업로드했던 원본 파일 상태로 100% 복구할 수 있습니다.

### 3) 저장 안 하고 닫을 때 확인 경고
* 셀 수정 후 저장하지 않은 상태(`hasChanges === true`)에서 모달 창을 닫으려 하거나 Esc를 누르면:
  - `"저장되지 않은 변경사항이 있습니다. 저장하지 않고 닫으면 작업 내용이 사라집니다."` 확인 다이얼로그를 띄워 실수를 원천 방지합니다.

### 4) 기존 편집기(SheetJS 경량 모드) 토글 지원
* 툴바 상단에 **`[ExcelJS (서식보존)]`** 과 **`[SheetJS (경량)]`** 선택 스위치를 제공하여, 사용자가 원할 경우 언제든 기존 SheetJS 모드로 저장할 수 있습니다.

### 5) 오피스 단축키 지원
* 엑셀 편집 창 내에서 **`Ctrl + S`** (Mac: `Cmd + S`) 입력 시 브라우저 기본 HTML 저장창이 뜨지 않고, **메모 내부 엑셀 저장 및 반영(`handleSave`)**이 즉시 트리거됩니다.
* *(참고: 자동 저장은 사용자 요구사항에 따라 5단계에서 구현될 예정이며, 현재 1단계에서는 수동 저장 및 Ctrl+S를 지원합니다.)*
