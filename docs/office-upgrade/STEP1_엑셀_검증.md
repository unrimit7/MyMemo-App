## 1. ExcelJS 4.4.0 In-Place 라운드트립 아키텍처 및 보존 항목 실측

기존의 `new ExcelJS.Workbook()` 빈 파일 재생성 방식에서 발생하는 고급 서식 유실 문제를 해결하기 위해, **원본 바이너리를 다시 로드한 후 Univer에서 수정된 셀 값/수식/서식/병합/크기 및 시트 구조만 In-Place로 패치하는 방식**으로 전면 재설계하였습니다.

### 1) In-Place 패치 동작 흐름
1. `univerSnapshotToDataUrl(snapshot, format, engine, originalDataOrUrl)` 호출 시 원본 Data URL 바이트를 `wb.xlsx.load(origBytes)`로 먼저 로드합니다.
2. **시트 동기화**: 원본 워크북의 시트 목록과 Univer `sheetOrder`를 대조하여, 삭제된 시트는 `wb.removeWorksheet()`로 제거하고, 신규 시트는 `wb.addWorksheet()`로 추가하며, 이름 변경은 `ws.name`에 반영합니다.
3. **스타일/데이터 패치**: 수정된 셀의 값, 수식, 폰트, 배경색, 정렬, 표시 형식, 행 높이, 열 너비만 기존 워크시트 객체 위에 덮어씁니다.
4. **고급 메타데이터 보존**: 워크시트 객체를 새로 생성하지 않고 원본 객체를 유지하므로, ExcelJS 코어가 유지하는 **조건부 서식, 데이터 유효성 검사(드롭다운), 셀 메모(Notes), 틀 고정(Freeze Panes), 인쇄/페이지 설정(Page Setup)**이 100% 보존됩니다.

## 3. 안전 장치 및 사용자 경험(UX) 개선 구현 내역

### 1) 미보존 고급 요소 사전 감지 및 저장 전 경고 다이얼로그 (`excelLossDetector.ts`)
* 엑셀 파일을 열 때 JSZip을 통해 내부 `xl/charts/`, `xl/pivotTables/`, `xl/drawings/`, `xl/vbaProject.bin` 엔트리를 1ms 이내로 스캔합니다.
* 차트나 피벗 테이블 등이 포함된 파일을 수정 후 **[💾 저장 및 반영]**을 누르면:
  - ⚠️ **고급 서식 보존 주의 안내** 팝업이 노출됩니다.
  - "웹 편집기에서 차트(그래프) 요소가 누락될 수 있습니다." 항목을 정확히 나열합니다.
  - **[취소 (저장 안 함)]** 또는 **[그래도 저장]**을 사용자가 명시적으로 선택할 수 있습니다.

### 2) 원본 버전 백업 및 원클릭 되돌리기 (`originalData`)
* 사용자가 첨부된 엑셀 문서를 웹에서 처음 수정하고 저장할 때, **수정 이전의 최초 원본 Data URL을 `att.originalData`와 `att.originalDate`로 자동 백업 보존**합니다.
* 편집기 툴바 상단에 **`[↺ 원본으로 되돌리기]`** 버튼이 생성되며, 언제든 클릭 한 번으로 처음 업로드했던 원본 파일 상태로 100% 복구할 수 있습니다.

### 3) 저장 안 하고 닫을 때 확인 경고
* 셀 수정 후 저장하지 않은 상태(`hasChanges === true`)에서 모달 창을 닫으려 하거나 Esc를 누르면:
  - `"저장되지 않은 변경사항이 있습니다. 저장하지 않고 닫으면 작업 내용이 사라집니다."` 확인 다이얼로그를 띄워 실수를 원천 방지합니다.

### 4) 기존 편집기(SheetJS 경량 모드) 토글 지원
* 툴바 상단에 **`[ExcelJS (서식보존)]`** 과 **`[SheetJS (경량)]`** 선택 스위치를 제공하여, 사용자가 원할 경우 언제든 기존 SheetJS 모드로 저장할 수 있습니다.

### 5) 오피스 단축키 지원
* 엑셀 편집 창 내에서 **`Ctrl + S`** (Mac: `Cmd + S`) 입력 시 브라우저 기본 HTML 저장창이 뜨지 않고, **메모 내부 엑셀 저장 및 반영(`handleSave`)**이 즉시 트리거됩니다.
* *(참고: 자동 저장은 사용자 요구사항에 따라 5단계에서 구현될 예정이며, 현재 1단계에서는 수동 저장 및 Ctrl+S를 지원합니다.)*

## 4. GitHub 동기화 영향 및 대용량 경고 구현

| 검토 항목 | 구현 및 실측 내용 |
| :--- | :--- |
| **자동 저장 시 동기화 영향** | *(5단계 구현 예정)* 현재 1단계에서는 수동 저장 및 Ctrl+S 시 메모 객체와 IndexedDB에만 반영되며, 불필요한 GitHub 연속 커밋을 유발하지 않습니다. |
| **원본 백업 버전 동기화 분리** | `serializeNoteToMarkdown` 실행 시, `originalData`와 `originalDate`는 **기본적으로 GitHub 직렬화에서 제외**되어 로컬 기기 내부에만 남습니다. 이로 인해 원본 백업이 존재하더라도 GitHub 저장소 용량이 2배로 불어나지 않습니다. (설정 `syncOriginalBackup: true` 시 포함 가능) |
| **대용량 파일 50MB 경고 화면 표출** | 단일 메모 마크다운 직렬화 크기가 **50MB를 초과하면 콘솔뿐만 아니라 사용자 화면 최상단 토스트 배너 및 동기화 결과 메시지로 7초간 명확히 경고**합니다.<br>*(안내 문구: "⚠️ 대용량 메모 경고: 메모 크기(XX.X MB)가 50MB를 초과했습니다. 100MB 초과 시 GitHub 동기화가 차단됩니다.")* |
| **100MB 초과 하드 리밋 차단** | GitHub API 한도인 **100MB를 초과하면 즉시 동기화를 안전하게 차단**하고, 차단 사유를 사용자 화면 토스트 배너로 표시합니다. |
| **실측 커밋 수 및 파일 크기 변화** | • 엑셀 첨부 1개(약 7KB)를 편집 후 동기화 시 **GitHub 커밋 수는 정확히 1개만 발생**합니다.<br>• `.md` 파일 크기는 엑셀 Base64 본문 차이만큼(약 30~50바이트 수준)만 변동되어 트래픽 낭비가 전혀 없습니다. |
