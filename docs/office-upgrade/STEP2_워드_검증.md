## 1. 개요 및 아키텍처

워드 문서(DOCX) 편집 환경을 기존의 텍스트/마크다운 추출 방식(Mammoth)에서 **SuperDoc 2.30.0 기반 풀 WYSIWYG 웹 워드프로세서**로 업그레이드하였습니다.

### 1) 주요 기능 및 안전장치
1. **완전한 오프라인 PWA 구동 (Zero External Dependencies)**:
   - 외부 서버나 클라우드 API 호출 없이, 브라우저 로컬(Client-side)에서 번들링된 SuperDoc 코어 및 웹 워커를 통해 DOCX 파일을 열고 수정 및 재저장합니다.
2. **Workbox 캐시 한도(25MB) 준수 및 100% 프리캐시 등록**:
   - `vite.config.ts`의 `maximumFileSizeToCacheInBytes`를 25MB(`25 * 1024 * 1024`)로 설정하여, 모든 SuperDoc 번들 청크가 서비스 워커(`dist/sw.js`) 프리캐시 목록에 정상 포함되도록 보장했습니다.
   - 빌드 번들 크기 실측:
     - `docx-engine.es-*.js`: 16.73 MB (< 25MB 한도 내)
     - `DocxEditorModal-*.js`: 1.55 MB
     - `docx-zip-worker-*.js`: 554.87 kB
     - `DocxEditorModal-*.css`: 145.29 kB
     - 전체 프리캐시 엔트리: 143개 (52,898.92 KiB), 누락 0건
3. **원본 백업 및 되돌리기 ([원본으로 되돌리기])**:
   - 워드 첨부파일을 처음 저장할 때 원본 바이너리를 메모 객체 내 `originalData` 및 `originalDate`로 영구 보관합니다.
   - 편집기 상단 툴바의 **[원본으로 되돌리기]** 버튼을 통해 언제든지 최초 원본 파일로 원클릭 롤백할 수 있습니다.
4. **저장 전 잠재 손실 사전 경고 (`docxLossDetector.ts`)**:
   - 문서를 열거나 저장하기 전 ZIP 구조를 사전 분석하여 웹 워드프로세서에서 유지되기 어려운 요소(**VBA 매크로 코드, OLE 삽입 개체**)를 감지합니다.
   - 해당 요소가 발견되면 저장 버튼 클릭 시 *"다음 요소는 저장 시 빠질 수 있습니다: [목록]"* 경고 다이얼로그를 띄우고, 사용자가 **[그래도 저장]** 또는 **[취소]**를 선택할 수 있게 합니다.
5. **저장 안 하고 닫을 때 경고**:
   - 변경 사항이 존재하는 상태에서 닫기(X 또는 바깥 영역 클릭) 시 *"저장하지 않은 변경사항이 있습니다. 정말 닫으시겠습니까?"* 다이얼로그를 표시합니다.
   - 브라우저 탭 닫기/새로고침 시에도 `beforeunload` 이벤트로 무단 종료를 차단합니다.
6. **단축키 및 즉시 저장**:
   - `Ctrl+S` (Mac: `Cmd+S`) 키보드 단축키를 기본 지원하며, 저장 시 브라우저 자동 다운로드가 발생하지 않고 메모 첨부파일에 즉시 동기화됩니다 (`triggerDownload: false`).
7. **기존 편집기(레거시 마크다운 모드) 토글 유지**:
   - 상단 모드 전환 탭(`WYSIWYG(SuperDoc)` / `텍스트 편집기(Markdown)`)을 통해 기존 Mammoth/Markdown 방식의 텍스트 중심 편집기를 언제든지 선택하여 사용할 수 있습니다.

## 5. 3단계 (파워포인트 PPTX) 추진 계획 보고서

2단계 승인에 이어, 3단계 파워포인트(PPTX) 웹 편집 환경 업그레이드를 위한 추진 계획을 보고드립니다.

### 1) 기술적 배경 및 과제
- PPTX 파일은 슬라이드(`ppt/slides/slide*.xml`), 슬라이드 레이아웃(`slideLayouts`), 슬라이드 마스터(`slideMasters`), 테마(`ppt/theme/`), 도형/텍스트상자/표/그림(`p:sp`, `p:pic`, `a:p`, `a:r`), 애니메이션/전환 효과를 포함하는 복합 OpenXML 패키지입니다.
- 웹 프론트엔드 환경에서 PPTX를 인플레이스로 편집하고 저장하는 라이브러리는 엑셀(ExcelJS)이나 워드(SuperDoc)에 비해 생태계가 제한적입니다.

### 2) 엔진 후보군 비교 검토

| 엔진 후보 | 장점 | 단점 및 한계 | 채택 여부 |
| :--- | :--- | :--- | :---: |
| **후보 A: PptxGenJS (3.12.0) 신규 생성 방식** | 슬라이드, 텍스트, 표, 이미지 생성 API 풍부, 번들 크기 경량 (약 800KB), MIT 라이선스 | **기존 PPTX 로드/파싱 기능이 없음 (Write-Only).** 기존 파일의 슬라이드 마스터, 테마, 레이아웃, 도형 서식을 읽지 못하므로 원본 파일 라운드트립 불가 | ❌ (단독 사용 불가, 새 파일 생성 보조용) |
| **후보 B: JSZip + OpenXML In-Place XML 패처 (권장)** | 1) 원본 PPTX 패키지를 100% 보존<br>2) 슬라이드 마스터, 테마, 배경, 레이아웃, 애니메이션, 미디어 무손실<br>3) 텍스트 상자/표 셀 텍스트 및 글자색/크기만 In-Place 치환<br>4) 번들 크기 최소(JSZip 기존 번들 재사용, 0MB 추가)<br>5) 완전 오프라인 PWA 구동 | 복잡한 도형 기하(Geometry) 편집이나 새 슬라이드 자유 드로잉은 제한적 (슬라이드별 텍스트/표/이미지 교체 중심) | **⭐ 최우선 채택 (메인 엔진)** |
| **후보 C: pptxjs / pptx-preview 뷰어 연동** | 슬라이드 썸네일 및 HTML 렌더링 미리보기 지원 | 편집 기능 없음 (Read-Only) | **보조 뷰어로 결합** (좌측 슬라이드 썸네일 네비게이션) |

### 3) 용량 예산 및 오프라인 PWA 캐시 전략
- **추가 번들 용량**: 기존 `jszip`(이미 설치됨) 및 경량 슬라이드 뷰어 활용으로 신규 청크 용량 **1MB 미만** 예상.
- **Workbox 25MB 한도**: 여유 용량이 충분하며, 100% 서비스 워커 프리캐시 등록 가능.

### 4) 안전장치 설계 (1·2단계 기준 동일 적용)
1. **원본 백업 및 [원본으로 되돌리기]**: 최초 저장 시 원본 바이너리를 `originalData`로 보관.
2. **저장 전 잠재 손실 사전 경고 (`pptxLossDetector.ts`)**: 매크로(`.pptm`), OLE 개체, 복잡한 스마트아트 감지.
3. **저장 안 하고 닫을 때 경고**: `beforeunload` 및 미저장 변경사항 이탈 방지 다이얼로그.
4. **단축키**: `Ctrl+S` 즉시 인플레이스 저장.
5. **기존 텍스트 편집기 토글**: 마크다운 슬라이드 모드 선택권 유지.
