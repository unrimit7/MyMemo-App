# STEP6 오피스 미리보기·편집 전반 점검

작성: 2026-11-16. 실제 앱(`npm.cmd run dev`, 오프라인은 `vite preview` 빌드본)에서 Playwright로 눌러 보고 판정했다.
표의 수치는 아래 스크립트 출력(`docs/office-upgrade/out/step6/*.json`, `*.txt`)에서 옮겼다.

- 1차: `node scripts/run_step6_audit_playwright.mjs` → `out/step6/audit_result.json` (OK 73, N/A 2, WARN 1)
- 2차: `node scripts/run_step6_phase2_playwright.mjs` (`PHASE=edit,k2,export` / `doc` / `big`, 오프라인은 `PREVIEW=1 PHASE=offline`) → `out/step6/phase2_result_*.json`, `phase2_log_*.txt`
- 시험 파일: `samples/real/`(기존 가상 파일), `samples/step6/`(가상 PDF 3쪽, 숨긴 행·열 엑셀). 10MB 엑셀은 `node scripts/make_step6_samples.mjs`로 만들고 저장소에는 넣지 않는다(.gitignore).
- 표기: ✅ 확인함, ⚠️ 알려진 한계(사유), ➖ 해당 없음. "사실"은 스크립트·파일로 확인한 것, "추정"은 확인하지 못한 판단이다.

표 보충 (사실):
- 오프라인: 빌드본에서 서비스 워커 활성 후 네트워크를 끊고 새로고침. 다섯 형식 모두 카드가 뜨고 편집기(PPT는 큰 화면)가 오류 문구 없이 열렸다. 오프라인 상태에서 저장 버튼까지 누른 시험은 하지 않았다(저장은 기기 안 IndexedDB만 쓰므로 될 것으로 추정). 한글 편집기를 열 때 rhwp가 자체 서비스 워커 등록에 실패했다는 콘솔 오류가 1건 있었고, 편집기 동작에는 영향이 없었다.
- PDF 내보내기: 펼친 것만·모두 펼쳐서 → 글자 4425자, 표 4, 그림 4, SVG 3, PPT 글 포함. 첨부 빼기 → 228자(파일 이름만). 점검 메모에는 접힌 토글이 없어서 앞의 두 방식 결과가 같다.
- 닫기 버튼: 다섯 형식의 큰 화면 뷰어와 편집기에서 세 너비 모두 닫기 버튼이 화면 안에 있었다. Esc는 큰 화면 뷰어에서 확인했고, 편집기 Esc는 이번에 따로 시험하지 않았다(STEP5 결과 유지).
- 엑셀 요소 비교의 "병합 범위 안쪽 칸 서식 11개"는 B16:F18 병합 안쪽 칸의 테두리·표시 형식이다. 화면과 인쇄에는 병합의 바깥 칸만 쓰이므로 보이지 않는다(추정). ExcelJS가 불러올 때 병합 안쪽 칸에 첫 칸 서식을 복사하는 동작으로 보인다.
